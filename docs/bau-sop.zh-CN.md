# CA-Manager 证书日常运维标准作业程序（BAU SOP）

> [English](bau-sop.md) | 简体中文
>
> 基于 CA-Manager Web 界面的证书日常运维（Business As Usual）标准作业程序。
> 操作路径均按系统实际菜单编写；部署、架构与故障排查细节见 [运维手册](operations.zh-CN.md)。

## 2. 目的与范围

**目的**：规范基于 CA-Manager 开展的证书日常运维作业，明确各级人员的标准操作步骤、完成标准与异常升级路径，保证证书服务连续性与操作可审计。

**范围内（通过 CA-Manager 完成）**：证书申请与审批、证书颁发/拒绝、证书吊销与取消吊销、CRL 发布与周期管理、到期证书跟进、证书模板启停、用户与权限管理、审计日志归档。

**范围外（仍需在 CA 服务器本地/AD 侧处理，遇到时按第 7 节升级）**：

- 企业 CA 自身证书的续期
- AD CS 服务（CertSvc）的启停
- AD CS 数据库维护与备份
- AD 中证书模板对象的创建/修改（CA-Manager 仅能启停已存在的模板）

## 3. 角色与职责

| 角色 | 系统权限 | BAU 职责 |
|------|---------|---------|
| 普通用户 User | 提交申请（需审批）、生成 PGP 密钥；仅可见本人证书 | 按需提交申请、保管好 PFX 与私钥口令、到期前重新申请 |
| 证书操作员 Operator | 全局可读 + 颁发/拒绝/重提交、吊销/取消吊销、发布 CRL、审批普通用户申请 | **日常作业主责**：处理审批与请求队列、执行吊销、发布 CRL、跟进到期证书 |
| 审计员 Auditor | 全局只读 + 审计日志 | 月度抽查审计记录、复核例行作业完成情况 |
| 系统管理员 Admin | Operator 权限 + CRL 周期、模板启停、用户管理、通知/LDAP 设置 | 账号与权限维护、CRL 周期调整、通知链路保障、审计归档监督 |
| 平台/AD 管理员（升级对象） | CA 服务器本地 | 处理范围外事项（CertSvc、CA 证书续期、AD 模板对象、数据库备份） |

> 建议通过 AD 组映射（`CA-Manager-Admins` / `CA-Manager-Operators`）授权，本地 `admin` 账号仅作应急后门。

## 4. 例行作业日历

### 4.1 每个作业日（Operator）

| # | 作业 | 入口 | 完成标准 |
|---|------|------|---------|
| D1 | 08:00 后查看每日汇总邮件（证书到期 / CA 证书到期 / CRL 超期 / 待审批积压 四类事件） | 邮箱 | 有事件项的，逐项转入对应流程处理；未收到邮件 → 按 EXP-05 处理 |
| D2 | 处理 **证书审批**（`/approvals`）队列：批准或拒绝 | 证书审批 | 当日清零，或积压 ≤ 【N】件并登记原因 |
| D3 | 处理 **请求处理**（`/requests`）中 pending / failed 请求 | 请求处理 | pending 请求已重提交或拒绝；failed 请求已归纳原因（W2 汇总） |
| D4 | 查看 **仪表盘**（`/dashboard`）：CA 状态、待处理数、30 天内到期数 | 仪表盘 | 无红色告警；有告警转入对应流程 |

### 4.2 每周（Operator）

| # | 作业 | 入口 | 完成标准 |
|---|------|------|---------|
| W1 | 检查 **到期提醒**（`/expiring`）30 天内到期的证书，逐一确认责任人对续期事宜已响应（系统会自动邮件通知申请者，此处为人工跟进兜底） | 到期提醒 | 清单内每张证书已确认处理方式（重签/报废），并记录于【台账/工单】 |
| W2 | 归纳本周 failed 请求与被拒绝申请的原因 | 请求处理 | 异常模式（如模板错、SAN 不合规）反馈给申请人或升级 Admin |
| W3 | 核对 **CA 与 CRL**（`/ca`）页显示的 CRL 下次发布时间正常、未超期 | CA 与 CRL | CRL 未超期；超期 → 按 EXP-04 处理 |

### 4.3 每月（Operator + Auditor）

| # | 作业 | 责任人 | 完成标准 |
|----|------|--------|---------|

| M3 | 从 **CA 与 CRL** 页下载当前 CRL 并查看内容解析，确认吊销记录与发布周期正常 | Auditor | 抽查结论记录在案 |
| M4 | 检查 CA 服务器 `publish\data\camgr.db` 大小与磁盘余量 | Admin | 磁盘余量充足；审计表过大时归档后清理 |

|----|------|---------|

## 5. 标准作业流程

通用约定：

- 登录地址 `https://<主机名>:8443`；登录失败 5 次锁定 15 分钟，会话 8 小时滑动过期。
- 所有敏感操作（吊销、颁发、配置变更等）自动写入审计日志，无需人工登记；需要业务背景的（如"应用方要求提前更换"）记入【工单/台账】。
- 涉及私钥的操作（自助生成、PFX 下载）完成后，申请人须立即取走并妥善保存；服务器侧不留存任何明文密钥。

### SOP-01 审批并颁发普通用户的证书申请

- **触发**：审批队列出现新申请（普通用户在 **提交申请** 页提交，支持粘贴 CSR 与自助生成两种方式）。
- **权限**：Operator / Admin。
- **步骤**：
  1. 进入 **证书审批**（`/approvals`），查看申请详情：申请人、用途、模板、主题与 SAN、有效期。
  2. **核实申请合规性**：用途与模板匹配、SAN 域名归属申请部门、无超出惯例的通配符/长有效期。存疑的先与申请人确认（线下渠道）。
  3. 确认无误点击 **批准**——系统此时才真正把请求提交给 CA 颁发（自助生成的私钥以申请人自设口令加密暂存）。
  4. 不合规的点击 **拒绝** 并填写理由；暂存密钥立即销毁，申请人会收到拒绝结果。
  5. 提醒申请人：颁发后到 **证书管理** 页凭申请时自设的口令**一次性下载 PFX**，下载后服务器端暂存私钥即销毁。
- **完成标准**：队列中该申请状态为已批准/已拒绝；对应证书可在 **证书管理** 查询到（已颁发）。
- **注意**：CSR 模式私钥在申请人本机，PFX 仅对自助生成模式适用；不要批准与本人/本部门无关的 SAN 申请。

### SOP-02 处理 pending / failed 请求（请求处理队列）

- **触发**：**请求处理**（`/requests`）页出现 pending（等待 CA 侧处理，常见为需管理员审批的模板）或 failed 请求。
- **权限**：Operator / Admin。
- **步骤**：
  1. 查看 pending 请求的 RequestId 与模板，确认确属应颁发的 → 点击 **颁发**（等效 `certutil -resubmit`）；不应颁发的 → **拒绝**。
  2. failed 请求查看失败原因；属申请人资料问题的退回重提，属模板/CA 配置问题的升级 Admin。
  3. 反复失败的请求记录 RequestId 与 HRESULT，按第 7 节升级。
- **完成标准**：队列当日清零或说明原因。

### SOP-03 操作员直接提交证书（免审批）

- **触发**：运维侧自用证书（如服务器证书）需直接签发。
- **权限**：Operator / Admin（Operator 提交的 CSR 直接生效，不走审批队列）。
- **步骤**：
  1. 进入 **提交申请**（`/new-request`），选择模式：
     - **粘贴 CSR**：私钥留在申请机，粘贴 PEM/Base64 CSR，选模板提交；
     - **自助生成**：由服务器代生成密钥对（支持多域名/IP 混合 SAN），设置 PFX 口令，颁发后下载 PFX。
  2. 颁发结果在 **证书管理** 页查询，可下载 CER/PEM。
- **完成标准**：证书状态为已颁发；自助生成的 PFX 已下载并口令交付到位。
- **注意**：自助生成模式的私钥经服务器内存生成，仅适合内部/测试用途；生产服务器证书建议 CSR 模式。

### SOP-04 吊销证书

- **触发**：证书对应私钥泄露、主机退役、证书信息错误、单位要求终止使用等。
- **权限**：Operator / Admin。
- **步骤**：
  1. 在 **证书管理**（`/certificates`）按序列号/关键字查到目标证书，打开详情核对主题与指纹，**务必确认是目标证书**。
  2. 点击 **吊销**，选择原因（7 种），按需填写失效日期。
  3. 在确认框中**输入完整序列号**完成二次确认。
  4. 进入 **CA 与 CRL**（`/ca`）页确认当前 CRL 的下次发布时间；需要立即生效的执行 SOP-05 手动发布 CRL。
- **完成标准**：证书状态变为已吊销；新 CRL 发布后全网生效。
- **风险与注意**：
  - **除 `CertificateHold` 外吊销不可逆**，误吊销只能重新签发，操作前务必核对指纹。
  - 私钥泄露类事件同时按安全事件流程上报【安全团队】。

### SOP-05 手动发布 CRL / Delta CRL

- **触发**：吊销后需立即生效；例行发布检查发现异常；发布周期调整后需要立即落地。
- **权限**：Operator / Admin。
- **步骤**：
  1. 进入 **CA 与 CRL**（`/ca`），查看当前 CRL 周期与下次发布时间。
  2. 点击 **发布 CRL**（完整 CRL；需要缩短吊销生效窗口时可同时发布 Delta CRL，等效 `certutil -CRL` / `certutil -CRL delta`）。
  3. 发布后下载 CRL 并查看内容解析，确认本次吊销记录已包含、下次更新时间正确。
- **完成标准**：CRL 序号/ThisUpdate 前移，目标证书出现在吊销列表中。
- **注意**：CRL 发布后对依赖 CDP 的全网客户端生效，请勿在业务高峰随意频繁发布。

### SOP-06 取消吊销（仅 CertificateHold）

- **触发**：以 `CertificateHold` 原因临时吊销后确认恢复使用。
- **权限**：Operator / Admin。
- **步骤**：
  1. 在 **证书管理** 找到该证书 → **取消吊销**（等效恢复，证书立即恢复有效）。
  2. 如曾发布过包含该吊销记录的 CRL，执行 SOP-05 重新发布 CRL 使恢复生效扩散。
- **完成标准**：证书恢复有效状态。
- **注意**：`CertificateHold` 仅作短期临时措施；确认永久不需要的证书应改用正式原因重新吊销，避免长期 hold 挂账。

### SOP-07 调整 CRL 发布周期（管理员）

- **触发**：安全策略调整（如缩短吊销生效窗口）或当前周期不合理。
- **权限**：Admin。
- **步骤**：
  1. **CA 与 CRL**（`/ca`）页修改 CRL / Delta CRL 周期（Delta 设 0 表示禁用 Delta）。
  2. 手动发布一次 CRL 使新周期立即生效（SOP-05）。
  3. 确认页面上显示的下次发布时间已按新周期计算。
- **完成标准**：新周期生效且有审计记录；下游客户端（CDP 指向的分发点）能取到新 CRL。
- **注意**：周期过短会加重客户端拉取负担，调整前与安全团队确认基线。

### SOP-08 证书模板启停（管理员）

- **触发**：新模板上线（AD 侧已由平台管理员创建）或某模板停止签发。
- **权限**：Admin。
- **步骤**：
  1. **证书模板**（`/templates`）页查看已启用模板及其 AD 详情。
  2. 启用/停用目标模板（等效修改 CA 策略模块的 Templates 列表）。
  3. 通知相关申请人模板变更生效时间。
- **完成标准**：模板列表状态正确；有审计记录。
- **注意**：模板对象的创建/修改在 AD 侧完成，属范围外事项（升级平台/AD 管理员）。

### SOP-09 到期证书的续期跟进

- **触发**：每日汇总邮件的到期事件 / **到期提醒**（`/expiring`）页 30/60/90 天清单。
- **权限**：Operator / Admin（跟进）；User（重新申请）。
- **说明**：CA-Manager 不做自动续期；续期 = 申请人在到期前**重新提交一次申请**（旧证书到期自然失效，不需要吊销）。
- **步骤**：
  1. 每周从 `/expiring` 导出/核对 30 天内到期清单（W1 作业）。
  2. 确认系统邮件已送达申请者（机器账户/无邮箱证书自动跳过，需人工找到责任人）。
  3. 责任人重新提交申请的，走 SOP-01 审批；明确不再续用的，记录报废，到期后自然失效。
  4. 关注 **CA 证书到期告警**：CA 自身证书到期属范围外事项，立即升级平台管理员（提前 ≥【30】天）。
- **完成标准**：清单内证书均有处置结论（已重签 / 报废）。

### SOP-10 生成 PGP 密钥对

- **触发**：用户需要 OpenPGP 密钥用于文件加密。
- **权限**：除 Auditor 外均可用。
- **步骤**：
  1. **PGP 密钥**（`/pgp`）页选择算法（RSA/ECC）与长度，生成。
  2. **私钥仅在生成响应中返回一次**——立即下载保存，关闭页面后无法再次获取；服务器不留存任何密钥材料。
  3. 私钥遗失的只能重新生成并更新分发对象。
- **完成标准**：用户已将公钥分发、私钥离线妥存。

### SOP-11 审计日志查询与月度归档

- **触发**：安全抽查、事件溯源、月度例行（M1）。
- **权限**：Auditor / Admin 可查全量；支持按时间、用户、操作类型等条件查询与 CSV 导出。
- **步骤**：
  1. **审计日志**（`/audit`）页按条件筛选（如上月全部吊销操作）。
  2. 导出 CSV，存放至【归档路径】，命名如 `camgr-audit-2026-09.csv`。
  3. 抽查若干条与工单/台账交叉核对。
- **完成标准**：归档完成并在月度检查表登记；保留期 ≥【12 个月】。

### SOP-12 用户账号开通 / 变更 / 停用

- **触发**：人员入职、转岗、离职；角色调整。
- **权限**：Admin。
- **步骤**：
  1. **用户管理**（`/users`）页新增本地账号，或启用 AD 域登录后由域账号直接登录（按 `memberOf` 匹配角色映射组）。
  2. 分配最小角色：仅查询 → User；需要审批/吊销 → Operator；合规监督 → Auditor。
  3. 离职/转岗：立即停用本地账号；域账号通过将其移出角色映射组（或禁用域账号）回收权限。
  4. 新管理员账号首登强制改密；`initial-admin-password.txt` 用后即删。
- **完成标准**：账号与岗位一致，月度 M2 复核通过。

## 7. 异常处理与升级

### 7.1 升级路径

| 级别 | 对象 | 联系方式 |
|------|------|---------|
| L1 | 证书操作员（当班） | 【姓名 / 电话】 |
| L2 | CA-Manager 系统管理员 | 【姓名 / 电话】 |
| L3 | 平台/AD 管理员（CA 服务器、CertSvc、AD 模板） | 【姓名 / 电话】 |

### 7.2 常见异常处置

| 编号 | 现象 | 处置 |
|------|------|------|
| EXP-01 | 审批队列积压超过阈值【N 件 / 24 小时】 | Operator 增援清理；持续积压升级 L2 评估是否增补操作员 |
| EXP-02 | Web 页面无法访问/登录异常 | 平台管理员在 CA 服务器执行 `Restart-Service CA-Manager`；查事件日志 Source `CA-Manager`；未恢复升级 L3 |
| EXP-03 | 证书误吊销 | 若原因为 `CertificateHold` → SOP-06 取消吊销；其他原因**不可恢复**，立即按 SOP-01/SOP-03 重新签发并向证书使用方说明 |
| EXP-04 | CRL 超期告警（汇总邮件/CA 与 CRL 页） | 先在 Web 端手动发布 CRL（SOP-05）；发布失败说明 CertSvc 异常 → 升级 L3（范围外，需服务器本地处理） |
| EXP-05 | 每日汇总邮件未收到 | Admin 检查 **通知设置**：SMTP 配置、发送时间、收件人；点 **立即执行扫描** 与 **发送测试邮件** 验证链路 |
| EXP-06 | admin 密码遗忘 | CA 服务器 publish 目录执行 `.\CaMgr.Api.exe reset-admin`（生成临时密码，首登强制改密；服务可不中断） |
| EXP-07 | 账号被锁定（登录失败 5 次，锁 15 分钟） | 等待自动解锁；确需立即恢复由 Admin 在 **用户管理** 重置密码 |
| EXP-08 | 疑似私钥泄露事件 | 立即 SOP-04 吊销（原因选私钥泄露类）+ 发布 CRL，同时按安全事件流程上报，事后审计日志取证（SOP-11） |
